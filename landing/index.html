Modules

clientaddon/panorama/scripts

Panorama client

Runs inside Deadlock. No filesystem, no network and no second focus graph: every control is a pointer-driven panel.

openlock_shell.jswindow manager

Owns the catalog, taskbar, title bars, pins, drop grid, toasts, tools and console. Frames live game panels by tracking their real rect and moving them with a transform; the panel never leaves the game's tree.

refusesto invent a panel the game has not drawn; it binds later in a "not on screen" state.

openlock_layout.jslayout arbitration

Owns who gets this space: reserves the bar and per-window chrome insets, records each participant's pre-shell rect, and returns it when the shell closes.

refusesa participant that cannot fit; it is named, never clipped.

openlock_split.jssplit identity

Owns the durable key for a split of a discovered window, so a HUD rebuild or a renamed panel does not orphan its cells across a reload.

refusesa discovery name that is only a position; that window cannot be pinned.

openlock_popit.jscell editor

The root stays mounted with six sections; opening one reveals a contextual child, and Back closes the child rather than swapping the root out. It edits the selected window or live cell, never a second shell. The cell's edit and the chosen colour pair are saved in the same layout row.

refusesa target the game has not drawn; the cursor lists only panels that can be bound, never a declared window that is absent.

openlock_delivery.jslive delivery

Owns openlock.addons/a5d7cf25e0a40c0a06b836992556491d parsing, the version gate, atomic window-set replacement and the chunked XML node renderer.

refusesa payload over 4 MiB, a tree over 512 nodes or 24 deep, or a window set that names no delivered package. An unknown tag is drawn as a plain Panel, never executed.

openlock_audio.jsfour cues

Owns select, place, refuse and notify: four synthesized cues, one 40 ms throttle each, fired only by the shell's own actions.

refusesto fail the layout when the build has no PlayUISoundEvent; it runs silent.

openlock_shell_data.jsgenerated catalog

Owns the game layouts, windows, schemes, forms and build record read from the target install at generation time. Generated, never hand-edited.

refusesto bake a panel list from the build machine's game version; the catalog describes the install it targets.

src/Openlock/Shell

Host and package gate

C# in the Deadworks plugin reads packages before the client sees them. The client is not the security boundary; the reader is.

ShpPackage.csframe reader

Reads SHPKG002/SHPKG003 as read-only migration inputs: the 44-byte header, SHA-256 over the recipe, the 13-key window grammar and the artifact table. New packages use ModernPackage.cs and secure-shell.surface/<32 hex>.

refusesa bad magic, digest mismatch, truncated table, duplicate artifact, absolute or .. path, or a missing required key, with file and line.

AddonPackages.cspackage catalog

Owns discovery across the game's search paths, the 64-package catalog and the openlock.addons/a5d7cf25e0a40c0a06b836992556491d payload the client reads.

refusesa package over 16 MiB, a payload that would cross 4 MiB, an older revision, or a replacement that fails validation.

LayoutProfiles.cssaved layouts

Owns per-scheme window geometry, arrangement state and each cell's Popit style, written through a temporary file so a failed save cannot truncate the old one.

refusesa scheme or window id outside the grammar, out-of-range rectangles, a file over 256 KiB or a set over 400 windows.

VpkReader.csarchive reader

Owns the VPK directory tree and entry lookup used by the generators and the installer. It reads; it never writes an archive.

refusesa tree over 64 MiB, a malformed table, or an entry outside the archive.

ClientAddons.cssearch paths

Owns the game's own addon roots. The shell reads only directories the game already mounts, and lists what it actually found.

refusesto invent a mount for a package that is not on a search path.

ShellPackage.cs · LayoutTree.csgrammar and tree

Own the shell package's lanes, layers and title-bar projection, and turn source XML into a node tree the client can build with $.CreatePanel.

refusesan unknown lane, duplicate id, undeclared action target or unusable geometry; a refused package contributes no window.

tools/

Build and witness

A successful build is not evidence. The gate re-reads the installed bytes and refuses a tree that does not describe itself.

install.ps1 · release/install.ps1install

Own compile, pack, SHA-256, VPK magic, the search-path edit and the one-time .pre-openlock backup in a source install.

refusesa hash mismatch, an unreadable VPK, a path that escapes the checkout, or a search-path change while the client is running.

parity_check.pyparity gate

Owns five cells: repo, GitHub, browser surface, install and live client. It reads the installed VPK rather than the installer's record.

refusesa stale or hand-copied install, and treats a dev-grade tree that lags the worktree as drift.

shell_test_surface.pywitness page

Owns the eleven behavioural suites and writes docs/shell-test-surface.html with each command, exit status and check count.

refusesto call a suite passing when no browser or shell witness observed it; the card names the missing surface.

package_envelope.pyoptional envelope

Owns the optional signed record over a package surface: digest, authority, proof of work and an HMAC-SHA256 signature.

refusesdigest-mismatch, untrusted-key, insufficient-work, signature-invalid or unreadable-envelope. An unsigned package loads unchanged.

Refusals

Each refusal names a file, a line and a reason. Four boundaries cover the package frame and the installed bytes.

Boundary index

01 · Ingress 02 · Runtime 03 · Delivery 04 · Install

Every stage below names the fact it refuses. The shell data and the Performance window keep the same rows at runtime.

01

Ingress

package → parse

Before a package's recipe is parsed, the frame must hold. The reader checks the bytes, then the grammar; it never parses first and validates later.

  • SHA-256, fixed-timeThe 44-byte header names a digest over the recipe. A mismatch refuses the whole package before one window is read.
  • 16 MiB · 1 MiB · 64 MiBPackage, recipe and VPK tree ceilings. A file over its ceiling is refused before the reader allocates its contents.
  • 1,024 artifacts256-byte artifact paths, 4 MiB per artifact, relative only: no absolute path, no backslash, no . or .. segment.
  • envelopeAn optional signed record: digest, authority, proof of work and HMAC-SHA256. A declared envelope that fails contributes no records.
02

Runtime

host string → panel

Every host-supplied string is treated as hostile. The ceiling is checked before the parse.

  • 4 MiB payloadThe layout attribute and observer trees are refused over 4 MiB before JSON.parse; the addon payload has the same ceiling.
  • 400 · 64 · 256 KiBWindows per profile, profiles, and the saved file. Coordinates must be finite and inside the declared range.
  • whole-profile rejectOne bad row refuses the profile whole. It is never half-applied and never becomes a partial window set.
  • __proto__A scheme or window id of __proto__ is refused by name. A legacy geometry map skips active, tab, pinned, minimized and popit as state.
  • 8 tags · 512 nodes · 24 deepThe live renderer is closed to the tags it knows; anything else becomes a plain Panel, with no script, event handler or new resource path.
  • theme allowlistA theme can paint colour and opacity only. No URLs, layout, fonts or resource references; selectors and properties are allowlisted.
03

Delivery

revision → catalog

Live packages replace a catalog atomically. A refused replacement leaves the mounted version, its index and its signatures untouched.

  • version gateA lower revision is refused; the mounted version stays. The host treats the same version and digest as already mounted, and a same-version package with different bytes is refused.
  • apply or rejectThe candidate set is validated before commit. A failure during the write rolls the catalog, index and signatures back together.
  • 64 recordsA stream of refused archives drops the oldest refusal-only record, never a mounted package. The client log is a 64-line ring.
  • observer closeA delivered XML surface gets the shell's close affordance outside the XML, so a surface cannot trap the observer.
04

Install

bytes → claim

An install is a claim about bytes, so the gate re-reads the bytes. The installer's own success record is not accepted as proof.

  • SHA-256 releaseThe player archive is hashed against the published checksum. A mismatch refuses the install; a dropped download is retried.
  • VPK magic · pathsThe archive must parse, and an entry that escapes the archive root is refused before anything is copied.
  • package reposA checkout must stay under openlock-packages/; a wrong VPK magic, path escape or steam.inf mismatch is refused. A package cannot write fonts or gameinfo.gi, and its scripts never run.
  • five cellsRepo, GitHub, browser, install and live client are re-read. A dev-grade install that lags the worktree is a refusal.

What this page claims: the enforcement above is read from the tracked source and its suites. It is not a claim that every path was captured live. The delivery evidence separates what was seen in a running client from what was seen only in the harness: docs/DELIVERY.md. The suite cards are the witness: shell-test-surface.html.

Legacy to modern

One reader · one direction · one carrier

Each project grew its own package family: SHPKG002 and SHPKG003 frames, shploingus.recipe/30444cad3419800564faba6d4e252431, openlock.envelope/d593054cb466a871f47d4804b3e2f333, V4PKG001 and V4PKG002. The old frame digests are SHA-256 evidence verified before the rewrite; the modern identity is BLAKE3 over canonical content. The family target is one carrier, with canonical bytes and the signature outside the digest.

ReadLegacy frames enter a read-only decoder behind the streamer boundary. The source package keeps its bytes and its identity.
RepresentThe decoder produces an explicit compatibility record with its own schema, not whatever object the old reader returned.
Recorddle-migrate writes source and target ids, the old digest, the new name@rev+blake3 identity, fields lost by name, actor and ticket.
ReframeOnly the modern carrier is emitted: dl-enclave.pkg/7eda1d82c5a03cc74883059912e73f71, a canonical header, a content-addressed payload, and a Debian signature outside the BLAKE3 preimage.
BLAKE3 identity
name@<rev>+blake3:<64 hex> replaces SHA-256 as the modern content identity. The revision, framing, encryption and signature stay outside the preimage, so a reframe or re-sign does not move the package.
One carrier, typed modules
dl-enclave.pkg/7eda1d82c5a03cc74883059912e73f71 carries goose.mod/0aae19884ea41415867d1385deea60e3, goose.vanilla/109e73f54aaaa7e072bbcb452569ebde and goose.client/d6f8a8b171f8c253b095d99f92e95b4a as module schemas inside the carrier.
Canonical bytes
UTF-8, canonical serialization and a declared newline policy. Generated files record their generator, input identity and post-materialization identity.
Separate authority
BLAKE3 proves byte identity. The Debian signature over a domain-separated manifest proves who asserted the revision. Chunk digests belong to the transport; the package digest names the package.

Recorded in db-mc-indev/AGENTS.md §11, dl-enclave/docs/PACKAGE-FORMAT.md §6 and secure_shell_v2/docs/SECURE-SHELL-RESTORE@1.ARCHITECTURE.md §5–§7, §12.8. The migration tool is on the Phase 1 work list, so this section records the target state.

The migration is one-way; there is no downgrade path. An input the pipeline cannot honestly read is refused by name instead of converted: schema-not-read for legacy shploingus.recipe/4, foreign-versioning-idiom for planet-*, no-format-behind-domain for planet-package-v1, and excluded-format for VPK and compiled assets.

Addons

Deadworks packages are canonical secure-shell.package/<32 hex> directories whose payload is a secure-shell.surface/<32 hex> declaration. The shell verifies the BLAKE3 identity before reading the surface, then mounts only declared windows. Legacy SHPKG002/SHPKG003 frames remain a read-only decoder. A package that fails any row contributes no windows.

A package may declare

Every row is read by the host, then projected into the client.

  • window · content · lane: a window, what it draws and where it lives. An unknown content or lane refuses the package.
  • geometry · min-size · opacity · elevation: finite and inside the window grammar.
  • theme-role: selects a colour role. It cannot name a raw colour or load a resource.
  • pinnable · layout · behavior: the title-bar projection. Pin is offered only when pinnable is true.
  • layer · action: a tool layer. Actions are unique and their target window must be declared.
  • record-id: the stable row identity. A duplicate id refuses the package.

No package gets

These are not conventions. They are the reader's bounds.

  • script execution: the renderer is a closed tag and attribute map.
  • absolute or .. artifact path: the artifact table is relative-only.
  • unbounded payload: 16 MiB package, 4 MiB live payload, 1 MiB recipe.
  • write to gameinfo.gi, panorama/fonts or another addon's folder: the installer does not run package scripts.
  • __proto__ scheme or window id: refused by name before it reaches a map.
  • theme rule that loads a URL, moves a window or hides a control: colour and opacity only.

The catalog is data, not a second build: one entry in landing/tools/addons.json adds a card. It carries the package name, version, author, target build, a short note, optional facts and links to the download or source. The inline list below is the fallback when the catalog is not reachable.

Install

The release installer verifies SHA-256, refuses a bad archive, writes one pak01_dir.vpk, and adds one search path. If another shell already owns that filename, move it aside first: the installer replaces the file, it does not merge archives.

files

Download install.cmd and install.ps1

The latest GitHub release carries both files, the player VPK, its checksum and the MIT license.

place

Drop them in game/bin/win64

That is the folder holding deadlock.exe. The script finds the install from its own location.

install

Close Deadlock and double-click install.cmd

The shell window asks for the grade, verifies the archive, writes citadel/addons/mods/pak01_dir.vpk, and adds citadel/addons/mods to SearchPaths. Other addon folders are untouched.

boot

Start Deadlock

The shell boots from its own archive. No server or plugin is required for the UI.

Windows marks downloaded scripts, and the default policy refuses to run them before they start. install.cmd applies a process-scoped bypass for you. To run install.ps1 directly, first right-click it → Properties → Unblock, then choose "Run with PowerShell", or run powershell -ExecutionPolicy Bypass -File install.ps1 from that folder.

Building from source? The checkout installer also hashes the built and installed VPK, keeps the first replaced archive as pak01_dir.vpk.pre-openlock, and writes the build record the parity gate reads. Build notes
